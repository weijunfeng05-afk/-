# 专用岗位评分与岗位删除

评分维度来自旧版 `weijunfeng05-afk/resume-data` 的 `screening.py`，参考提交 `58028d0cadcc8260d3936cea1fd6ce2ea657c448`。本次仅迁移评分标准与人工复核要求，不迁移旧版候选人数据、密钥或模型供应商限制。

## 专用评分标准

| ToC 商业化产品运营 | 权重 |
| --- | --- |
| 用户增长、留存、转化及商业化结果 | 30% |
| ToC 产品/运营策略与落地 | 25% |
| 数据分析、实验和指标意识 | 20% |
| 跨团队协作与项目推进 | 15% |
| 结果 ownership 与复盘能力 | 10% |

| 内部提效 AI 产品经理 | 权重 |
| --- | --- |
| AI/大模型产品理解与真实实践 | 30% |
| 内部工作流洞察、提效场景与 ROI | 25% |
| 产品定义、原型、迭代和落地 | 20% |
| 数据、评测、风险与人机协同意识 | 15% |
| 跨团队推动与 ownership | 10% |

每维输出 0–100 分，程序乘以上述权重后求和，保留一位小数。不得把无证据当作零分或移除维度。专用标准固定保留全部五维，额外加分条件仅作为复核参考，不改变上述权重。

旧版只规定“高优先复核、中优先复核、低优先复核”三种措辞，没有定义分数线。当前 MVP 延续已有 80/60 边界，并由程序确定分类：明确硬性条件不满足时为低优先复核；否则核心信息、维度证据或硬性条件不足时为待补充信息；信息完整时 ≥80 为高优先、≥60 为中优先，其余为低优先。暂定分不参与正常排名。

详情补充：简历自述 AI 深度、核验置信度、个人贡献层级、优势、风险、未知信息、面试必核验项和 HR 人工复核建议。结论不得自动决定录用或淘汰。引用必须存在于简历原文；引用存在不代表语义判断已获证实。

## 现有岗位与结果

新建岗位默认选择 ToC 标准，可切换为内部提效 AI 或通用岗位匹配。旧岗位未保存评分标准时继续使用原通用标准；编辑岗位后可切换。AI 提取 JD 不会更改用户选择的标准。

切换评分标准会增加岗位版本；评分与提示词版本升级为 2，历史结果提示需要重新分析。升级前尚未完成的旧规则任务明确报错并允许重试，不使用新的规则伪装成旧快照。仍保留单岗位批量匹配的 MVP 操作方式，没有引入旧版同时跨两个岗位自动推荐的流程。

## 删除岗位

岗位卡片提供“删除”，确认框展示将删除的岗位名称和影响范围。确认后 `DELETE /api/jobs/{id}` 在数据库事务内删除岗位、岗位简历关联、该岗位全部任务及匹配结果。

简历记录与原文件保留，不影响它们在其他岗位的使用。执行中任务的记录和令牌随岗位删除，后台模型返回后不能重新写入该岗位结果。删除最后一个岗位后，界面回到新建岗位的空状态。该操作不可撤销；下线前请确认不再需要该岗位历史结果。
